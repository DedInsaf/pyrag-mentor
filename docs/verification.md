# Проверка этапов проекта

Запускайте команды из корня репозитория. Перед интеграционными проверками
выполните `poetry install`. Общая команда `poetry run pytest` проверяет порог
покрытия 70%. Для отдельных файлов используйте `--no-cov`.

| Шаг | Как проверить | Ожидаемый результат |
|---|---|---|
| 1. Окружение | `poetry check`, `poetry run python scripts/check_setup.py`, `git check-ignore .env infrastructure/.env` | Python 3.12, окружение готово, оба файла секретов игнорируются |

## Оценка режимов

```bash
poetry run python -m scripts.weather_data import
poetry run python -m scripts.weather_data eval
poetry run python -m scripts.weather_eval eval_datasets/city_0_10.json
```

В отчёте есть количество результатов и ошибок, точность температуры и погодного
условия, chrF. По умолчанию прогон использует правила. Для сравнения LLM запустите
ту же команду с `--engine yandexgpt` или `--engine huggingface`. Эта оценка
проверяет текст на архивных примерах, а визуальное качество проверяется
отдельно по исходному и обработанному фото.

## Как увидеть ручную проверку текста

Выберите в кабинете `full` и текстовый движок YandexGPT/Hugging Face.
Запись создаётся при оценке ниже 7, ошибке критика или провале валидации.
Если все ответы проходят проверку, очередь останется пустой. Для воспроизводимой
проверки с заданным состоянием используйте автоматический интеграционный тест.
После подтверждения повторный вызов confirm для того же ID должен вернуть 404.

## Соответствие теме курса

Методички описывают пример машинного перевода. В этом проекте память переводов
соответствует архиву погодных наблюдений, четыре языковые пары — четырём
городам, а глоссарий — карточкам условий съёмки. Вместо Ollama используются
YandexGPT и локальный Hugging Face для текста. Код обработки изображений
выполняется отдельно от агентов, которые проверяют текст прогноза.
Источники — [официальные ноутбуки шагов 1–12](https://github.com/CodeHunterOfficial/ArabovMKDeep/tree/main/IIRSI/Project).
