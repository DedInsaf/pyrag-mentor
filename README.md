# PyRAG Mentor — мультиагентный помощник по Python 3.12

> Рабочая тема проекта. Команда может уточнить предметную область на следующих
> этапах; слои БД, API и агентов отделены от неё и не потребуют полной переделки.

## Описание

PyRAG Mentor отвечает на вопросы начинающих разработчиков по Python 3.12 и
разбирает небольшие фрагменты кода. На вход система получает вопрос и,
опционально, код. На выходе пользователь получает понятный ответ, исправленный
пример, ссылки на использованные фрагменты базы знаний и оценку уверенности.

Ответ проходит независимую проверку агентов `Validator`, `Critic` и `Editor`,
работой которых управляет `Supervisor`. Для генерации используется YandexGPT
через API Yandex Cloud. HuggingFace Transformers предусмотрен как резервный
LLM-бэкенд. Агентские фреймворки (LangChain, LangGraph и аналоги) не
используются: оркестрация будет реализована самостоятельно.

## Для кого проект

Для студентов и начинающих Python-разработчиков, которым нужен ответ не только
с готовым кодом, но и с объяснением, проверкой корректности и ссылками на
документацию.

## Цель проекта

Создать проверяемую QA-систему, которая:

- отвечает на вопросы строго в рамках Python 3.12;
- обосновывает ответ найденными фрагментами официальной документации;
- проверяет синтаксис примеров и несуществующие имена API;
- итеративно улучшает слабые ответы;
- передаёт неоднозначные случаи человеку через Human-in-the-Loop.

## Планируемая архитектура

1. Гибридный поиск извлекает контекст из базы знаний с помощью BM25 и Qdrant.
2. YandexGPT генерирует черновик ответа с учётом найденного контекста.
3. `Validator` проверяет формат, ссылки, повторения и Python-код.
4. `Critic` выставляет оценки за точность, релевантность, полноту,
   понятность и подтверждённость источниками.
5. Если ответ не прошёл порог качества, `Editor` исправляет его, после чего
   цикл повторяется под контролем `Supervisor`.
6. Неуверенные ответы попадают в очередь ручной проверки.

## Данные

- **Справочник:** не менее 500 терминов, встроенных функций, исключений и
  сущностей стандартной библиотеки Python 3.12.
- **База знаний:** не менее 1000 фрагментов официальной документации и
  проверенных пар «вопрос — ответ».
- **Форматы импорта:** CSV и JSON.

Для каждого фрагмента будут храниться источник, URL, раздел документации,
версия Python и текст. Это позволит показывать пользователю происхождение
ответа и фильтровать устаревшие материалы.

## Стек технологий

- **Backend:** FastAPI, Pydantic Settings, SQLAlchemy async;
- **LLM:** YandexGPT API (основной), HuggingFace Transformers (резервный);
- **RAG:** BM25 (`rank-bm25`) + Qdrant + Reciprocal Rank Fusion;
- **Эмбеддинги:** `sentence-transformers`, мультиязычная модель MiniLM;
- **База данных:** PostgreSQL 16, SQLite для тестов;
- **Фоновые задачи и кэш:** Celery, Redis;
- **Human-in-the-Loop:** очередь неоднозначных ответов и обратная связь;
- **UI:** Streamlit;
- **Инфраструктура:** Docker, Docker Compose, Nginx;
- **Тестирование:** pytest, pytest-asyncio, pytest-cov;
- **Python:** 3.12;
- **Управление зависимостями:** Poetry 2.x.

## Быстрый старт

Требуется Python 3.12 и Poetry 2.x.

```bash
poetry config virtualenvs.in-project true --local
poetry install
cp .env.example .env
poetry run python scripts/check_setup.py
```

Для проверки доступа к YandexGPT заполните в `.env` переменные
`YANDEX_API_KEY` и `YANDEX_FOLDER_ID`, затем выполните:

```bash
poetry run python scripts/check_yandexgpt.py
```

Файл `.env` содержит секреты и исключён из Git. Никогда не добавляйте API-ключ
в код, README, коммиты или скриншоты.

## Настройка YandexGPT

1. Создайте сервисный аккаунт в Yandex Cloud.
2. Выдайте ему роль, позволяющую вызывать языковые модели.
3. Создайте API-ключ с областью `yc.ai.languageModels.execute`.
4. Скопируйте `.env.example` в `.env` и заполните ключ и идентификатор каталога.

По умолчанию используется модель `yandexgpt/latest` через нативный REST API.
Нативный асинхронный клиент уже используется базовым агентом; диагностический
скрипт позволяет отдельно проверить учётные данные.

## Запуск API

```bash
poetry run python run.py
```

После запуска доступны:

- `GET http://127.0.0.1:8000/healthz` — проверка состояния приложения;
- `GET http://127.0.0.1:8000/health` — проверка API и соединения с БД;
- `POST http://127.0.0.1:8000/auth/register` — регистрация;
- `POST http://127.0.0.1:8000/auth/login` — получение JWT;
- `GET http://127.0.0.1:8000/auth/me` — текущий пользователь;
- `http://127.0.0.1:8000/docs` — интерактивная документация Swagger;
- `http://127.0.0.1:8000/redoc` — альтернативная документация API.

Проверка из другого терминала:

```bash
curl http://127.0.0.1:8000/healthz
```

Настройки API, БД, LLM, Qdrant, Redis, JWT и логирования читаются из `.env`
классом `backend.core.config.Settings`. Логи одновременно выводятся в консоль
и записываются в `logs/pyrag-mentor.log`; файл ротируется при достижении 5 МБ.

Автоматические проверки:

```bash
poetry run pytest
poetry run ruff check backend tests run.py
poetry run black --check backend tests run.py
poetry run mypy backend tests run.py
```

## Запуск PostgreSQL и API в Docker

Для Docker не нужен настоящий ключ YandexGPT: пустые значения безопасны до
момента фактического вызова LLM.

```bash
docker compose -f infrastructure/docker-compose.yml up --build -d
curl http://127.0.0.1:8000/health
docker compose -f infrastructure/docker-compose.yml down
```

PostgreSQL хранит данные в именованном томе `postgres_data`, поэтому обычный
`down` их не удаляет. Пароли в Compose предназначены только для локальной
разработки; в публичном репозитории лежат лишь примеры и безопасные значения.

## Реализованные агенты

- `BaseAgent` задаёт единый асинхронный контракт и выбор YandexGPT или
  HuggingFace; для локальной генерации фиксируется `seed=42`.
- `Validator` выполняет детерминированные проверки ответа.
- `Critic` разбирает JSON-оценку устойчивым сканером и помечает невалидный
  ответ как `critic_failed`.
- `Editor` не делает лишний вызов LLM, если критик упал или замечаний нет.
- `Supervisor` выбирает бюджет итераций по начальной оценке, улучшает ответ и
  откатывается к лучшей версии при ухудшении, сохраняя журнал рассуждений.
